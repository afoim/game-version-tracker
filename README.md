# Game Version Tracker

采集原神、星穹铁道、崩坏3、绝区零、鸣潮、终末地、异环、蔚蓝档案日服和星塔旅人国服，输出 `data/games.json`，保持现有前端字段兼容。

```powershell
python src/main.py
```

Python 3.13，仅使用标准库。回归测试：`python -m unittest discover -s tests -v`。

日常维护由 ChatGPT 定时任务驱动：AI 直接通过 ChatGPT 自带 GitHub 连接器读取默认分支、核对公开来源、修改代码/测试/数据并提交推送；定时任务不得依赖 AgentDock、用户电脑或本地路径。详细流程见 `AI_RUNBOOK.md`。GitHub Actions 保留手动 deterministic fallback，并通过 CI 对涉及采集器、测试和数据契约的提交做回归验证，不承担每日 cron，避免与 AI 调度并发冲突。

`data/games.json` 在原有字段基础上新增向后兼容的 `sources` 数组。每条来源包含 `title`、`url`、`type`、`claims` 与 ISO 8601 `checked_at`，用于记录实际核验过的官方 API、官网、官方社区或必要的二级来源；采集/normalize 不得把已有信源静默擦除。

鸣潮将明确的上线文案与前瞻公告分开解析；预告中的更高版本不会成为当前版本。有完整年份和时间的上线公告按实际时间切换；3.6 的历史维护结束时间保留为仅绑定该版本的种子。新版本缺少可核实的日期时明确失败，绝不沿用旧版本日期或把前瞻日期当作上线日期。来源被限流、暂时不可达或返回 WAF 挑战时，鸣潮请求最多尝试三次。

采集器报错后仍检查其余游戏并打印逐项结果；任意一项失败则整批返回失败并保留上一份数据，避免发布缺失游戏或静默伪装成最新数据。输出通过临时文件原子替换，不删除其他数据文件。已结束的静态卡池 fallback 会在 normalize 阶段清空，避免“剩余 0 天”却仍伪装成当前 UP。

已知边界：部分游戏的版本日期、内容和卡池仍使用经当前官方信息核验的窄范围手工值；42 天等周期只能作为估算，不能当作官方确认时间。接口调用成功不证明这些手工字段仍有效。每天调度不能替代来源更新和解析维护，AI 需要持续检查硬编码和页面格式是否已经过期。
