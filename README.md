# Game Version Tracker

这是一个**纯 AI 驱动**的游戏版本数据仓库。

仓库不再包含 Python tracker、采集器、解析器、测试脚本或 GitHub Actions。日常维护只由 ChatGPT 定时任务完成：AI 使用 ChatGPT 自带的 GitHub 连接器读取/写入仓库，并联网独立核验公开信息，然后直接维护 `data/games.json`。

## 发布数据

唯一发布数据文件：

`data/games.json`

必须保持现有前端字段向后兼容，并为每个游戏维护 `sources` 数组。每条来源包含：

- `title`
- `url`
- `type`: `official_api | official | official_community | secondary`
- `claims`
- `checked_at`: ISO 8601

`sources` 只能记录本轮实际用于核验的数据来源；优先级为：官方 API / 官网 > 官方公告 / 官方社区 > 官方认证账号 > 可靠二级来源。

## 维护原则

- 每轮都重新读取默认分支最新内容，禁止基于旧快照覆盖远端修改。
- AI 必须联网独立核验 9 个游戏，而不是运行本地脚本。
- 仓库读取、JSON 校验和 sources 已存在都不代表维护完成；必须完成 9 个游戏逐项外部核验。
- 每个游戏必须有本轮真实读取的外部来源，搜索摘要、旧 sources 和模型记忆不算核验。
- 如果运行环境无法访问公开 Web 来源，必须报告平台级阻塞，不得刷新 `checked_at` 或伪造完成状态。
- 禁止依赖 AgentDock、用户电脑、本地路径、git CLI 或任何常驻机器。
- 禁止 force push。
- 不确定的时间必须保留“预计 / 未确认”语义，不能把历史周期推算写成官方确认。
- 前瞻/直播日期不能当作版本上线日期。
- 已结束卡池不能继续显示为当前 UP。
- 某个来源临时不可用时，保留上一次已验证数据，不得用猜测覆盖。
- `data/games.json` 必须始终保留完整 9 个游戏；不能提交残缺数据。
- 没有实质变化时不创建空提交。

详细维护流程见 `AI_RUNBOOK.md`。
